# Лендинг Узелка

Одностраничный лендинг личной CRM «Узелок»: объясняет, что это такое, и ведёт в приложение по кнопке «Завязать Узелок».

- Лендинг: https://завяжи-узелок.рф
- Приложение: https://app.завяжи-узелок.рф, его код — в репозитории [personal-crm](https://github.com/victoria-shaduro/personal-crm)

Страница статичная: без сервера, базы данных и JavaScript в браузере. Сделана на Astro и Tailwind CSS.

## Что где лежит

- `specs/02-лендинг.md` — спека: тексты, дизайн-токены, требования
- `design/landing/` — макет: эталонные HTML (`reference/`), исходники графики (`assets/`), скрипт, который рисует нити (`tools/gen_threads.py`)
- `src/components/` — блоки страницы, по одному файлу на блок; тексты страницы — здесь
- `src/styles/tokens.css` — цвета, шрифты и размеры; другие значения в компонентах не используются
- `src/config.ts` — адрес приложения для кнопок, заголовок вкладки и описание для поисковиков
- `astro.config.mjs` — настройки сборки, в том числе домен лендинга
- `public/` — картинки и фавикон, попадают на сайт как есть

## Что нужно установить

- Node.js 24 (LTS)
- pnpm

## Команды

| Команда | Что делает |
| --- | --- |
| `pnpm install` | устанавливает зависимости (один раз и после их обновления) |
| `pnpm dev` | запускает лендинг для разработки: http://localhost:4321, изменения видны сразу |
| `pnpm build` | собирает готовый лендинг в папку `dist/`; при выкатке эту команду выполняет GitHub Actions |
| `pnpm preview` | показывает собранный лендинг из `dist/` по адресу http://localhost:4321. Сервер работает в фоне; остановить его — `pnpm astro preview stop` |

## Как выкатить новую версию

Изменения нужно сохранить в git и отправить в ветку `main` на GitHub. Можно попросить агента: «Внеси изменения и выложи новую версию».

После `push` всё происходит автоматически:

1. [GitHub Actions](https://github.com/victoria-shaduro/personal-crm-landing/actions/workflows/deploy.yml) устанавливает зависимости из `pnpm-lock.yaml` и собирает `dist/` на Node.js 24 с версией pnpm из `package.json`.
2. `rsync --delete` загружает содержимое `dist/` в `/var/www/crm/landing` на сервере. Устаревшие файлы удаляются только в этой папке.
3. Уже настроенный nginx сразу отдаёт новую страницу по адресу https://завяжи-узелок.рф. На сервере ничего не собирается, перезапускать приложение или nginx не нужно.
4. Actions проверяет ответ главной страницы `200`, номер коммита в `deployment.json` и совпадение содержимого страницы с собранным файлом. Зелёный прогон означает, что новая версия проверена на публичном сайте.

Если прогон красный, нужно открыть его, исправить указанную ошибку и отправить новый коммит в `main`. Стенда и автоматического отката нет. При ошибке сборки загрузка на сервер не начинается.

## Настройки выкатки

- `.github/workflows/deploy.yml` — запуск после `push` в `main`; одновременные выкатки выполняются по очереди.
- `deploy/upload.sh` — отправка только готовой папки `dist/` по SSH с проверкой ключа сервера.
- `deploy/verify.sh` — проверка публичной страницы и версии после загрузки.
- Секрет репозитория `DEPLOY_SSH_KEY` — отдельный приватный ключ, созданный для этого лендинга. Он не хранится в git и не нужен на вашем компьютере для обычных обновлений.
- Переменные репозитория `DEPLOY_HOST`, `DEPLOY_KNOWN_HOSTS`, `LANDING_URL` — адрес сервера, его публичный SSH-ключ и адрес сайта.

Публичная часть ключа добавлена отдельной строкой к существующим разрешённым ключам пользователя `crmapp`. Для этого ключа сервер принудительно запускает `/usr/bin/rrsync -wo -munge /var/www/crm/landing`: разрешена только загрузка в папку лендинга, без командной оболочки и перенаправления портов. Остальные ключи и настройки nginx не меняются. На сервере установлен системный пакет `rsync`, в который входит `rrsync`.

Пароли и локальный `.env` для этой выкатки не нужны. При смене сервера или ключа нужно обновить соответствующие настройки GitHub; существующие секреты приложения трогать не нужно.
